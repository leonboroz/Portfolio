# 🧾 Первые выводы по созданию базы данных и её наполнению

1. **Ограничения в таблицах**  
   На этапе проектирования схемы базы важно тщательно продумывать ограничения (`PRIMARY KEY`, `FOREIGN KEY`, `CHECK`, `NOT NULL` и т.д.). Это экономит много времени на этапе загрузки.

2. **Изменения в структуре — это нормально**  
   Корректировать таблицы в процессе наполнения — не просто допустимо, а зачастую необходимо. Всё предусмотреть заранее невозможно.

3. **Об осторожности с удалением**  
   `ON DELETE CASCADE` — знаем, но не используем. Это может снести полтаблицы.  
   `TRUNCATE` — тоже табу: он быстрый, но слишком опасный.

4. **Практика — ключ к прогрессу**  
   Навыки и уверенность приходят только через постоянную работу руками.

5. **Нельзя полагаться только на `seed` при генерации**  
   Даже при фиксации сидов синтетические данные могут "поплыть" между сессиями. Особенно если есть зависимости между таблицами. Проверка необходима каждый раз.

6. **Фиксация данных обязательна**  
   Сначала зафиксировать сгенерированные данные, а затем работать только с этими файлами.

7. **Формат `pickle` — очень удобен для внутренних слепков**  
   Да, он нечитабелен напрямую, но:
   - сохраняет структуру точно,
   - снижает риск ошибок,
   - экономит время при повторной загрузке.

8. **Функция `map()` — использовать с осторожностью**  
   Нужно обязательно указывать **все** возможные значения. Пропущенные значения приведут к незаметным пробелам в данных. В большинстве случаев безопаснее использовать `np.where`.

9. **Пустые ячейки должны быть `pd.NA`**  
   `''` — это не пустая ячейка, а строка с пустотой. Это может привести к логическим ошибкам.  
   Заполнять пропуски допустимо только для визуализации или экспорта.
