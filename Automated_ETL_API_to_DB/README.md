# Automated_ETL_API_to_DB

## 📌 Описание проекта

Этот скрипт предназначен для автоматической загрузки данных из API, их очистки, трансформации и последующей загрузки в базу данных PostgreSQL. Также предусмотрена автоматизация через компиляцию в `.exe` и запуск по расписанию.


## 🛠 Установка

### 1. Установка зависимостей

Рекомендуется использовать виртуальное окружение:

```bash
python -m venv venv
venv\Scripts\activate  # Windows
# source venv/bin/activate  # Linux/macOS

pip install -r requirements.txt
```
### 2. Создать файл конфигурации для API `config_API.json`:

    ```json
    {
        "url": "https://api.example.com/data",
        "client": "your_client_id",
        "client_key": "your_client_key",
        "interval": 7
    }
    ```

### 3. Создать файл конфигурации для базы данных `config_DB.json`:

    ```json
    {
        "dbname_start": "postgres",
        "user": "your_db_user",
        "password": "your_db_password",
        "host": "localhost",
        "port": 5432,
        "new_base": "new_database",
        "new_schema": "public",
        "new_table": "data_table",
        "stroc": ["user_id INT", "oauth_consumer_key VARCHAR(255)", "lis_result_sourcedid VARCHAR(255)", "lis_outcome_service_url VARCHAR(255)", "is_correct BOOLEAN", "attempt_type VARCHAR(255)", "created_at TIMESTAMP"]
    }
    ```

### 📂 Конфигурационные файлы

Файлы конфигурации config_API.json и config_DB.json исключены из репозитория Git и добавлены в .gitignore по соображениям безопасности (содержат чувствительные данные, такие как ключи и пароли).

Для запуска проекта необходимо создать эти файлы вручную рядом со скриптом, согласно описанию в разделе "Установка".

## Запуск

###  Запуск вручную

python ETL_from_api_to_db.py

Убедитесь, что конфигурационные файлы находятся в той же директории, что и скрипт.


### Автоматизация (Windows Task Scheduler)

Скрипт можно автоматизировать следующим образом:

#### 1. Компиляция в .exe через PyInstaller

pyinstaller --onefile ETL_from_api_to_db.py

#### 2. Настройка в планировщике заданий Windows

Укажите путь к скомпилированному .exe в триггере.

Установите нужное расписание (ежедневно, еженедельно и т.д.).

Файлы config_API.json и config_DB.json должны находиться в той же папке, что и .exe.

В файл task_log.txt пишется факт запуска через планировщик.


## Описание классов и методов

## APIClient
### Методы:
get_instance(url=None, param=None) — возвращает единственный экземпляр класса (Singleton), подключается к API.
close_connect() — закрывает подключение к API.

## Dataload
### Методы:
load() — загружает данные с API.

## Transform
### Методы:
transf() — очищает и преобразует данные, подготавливая их к загрузке в базу данных.

## Database
### Методы:
connect_and_create_base() — подключается к базе данных, создаёт базу данных и таблицу.
loading_to_base() — загружает обработанные данные в таблицу базы данных.

## LogManager
###  Методы:
cleanup_old_logs() — удаляет старые лог-файлы.
Логирует все важные события, такие как ошибки или успешные операции.

### Логирование
Все логи хранятся в директории logs. Старые логи автоматически удаляются через заданное количество дней. Логи включают информацию об ошибках подключения, загрузке данных и успешных операциях.

## Отсутствие файла `.exe` в репозитории

Файл исполняемого приложения (`.exe`) **не включён в репозиторий** намеренно по следующим причинам:

- **Безопасность**: скомпилированный файл может содержать встроенные конфиденциальные данные (например, из конфигураций).
- **Размер и производительность**: `.exe` файлы часто занимают значительный объём, что увеличивает размер репозитория.
- **Портируемость**: бинарные файлы привязаны к конкретной операционной системе и архитектуре, что ограничивает использование.
- **Гибкость разработки**: исходный код проще обновлять и тестировать без необходимости пересборки и повторной загрузки исполняемого файла.

Кроме того, файл `.exe` исключён из репозитория через файл `.gitignore`, чтобы случайно не добавить его в систему контроля версий.

Рекомендуется самостоятельно собрать `.exe` из исходного кода с помощью инструментов, таких как [PyInstaller](https://www.pyinstaller.org/), перед автоматизацией запуска.
